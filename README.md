# LLM Fine-Tuning with LoRA for Text-to-SQL

A Google Colab notebook demonstrating how to fine-tune **TinyLlama 1.1B Chat** with **LoRA (Low-Rank Adaptation)** to generate SQL queries from natural-language questions and a database schema.

> **Scope:** This is a learning/demo project, not a production-ready Text-to-SQL system. Generated SQL should be validated and executed only in a controlled, read-only environment.

## What this project demonstrates

- Checking the runtime and available GPU in Google Colab
- Loading `TinyLlama/TinyLlama-1.1B-Chat-v1.0` in FP16
- Comparing base-model outputs before fine-tuning
- Preparing a small Text-to-SQL instruction dataset
- Attaching LoRA adapters with PEFT
- Fine-tuning and comparing outputs after training
- Saving the adapter separately from the base model

## Repository contents

- `llm_finetuning_lora_text_to_sql.ipynb` — main, output-cleared notebook
- `.gitignore` — excludes local environments, checkpoints, secrets, and generated model files

## Run in Google Colab

1. Open [Google Colab](https://colab.research.google.com/).
2. Choose **File → Upload notebook** and upload `llm_finetuning_lora_text_to_sql.ipynb`, or open the notebook from this GitHub repository in Colab.
3. Choose **Runtime → Change runtime type → T4 GPU** (or another compatible GPU, if available).
4. Run the cells from top to bottom.
5. The notebook installs its pinned Python dependencies in the setup cell and downloads the base model and dataset when required.

The first run needs an internet connection to download packages and model files. GPU availability and runtime limits depend on your Colab plan and current capacity.

## Model and method

- **Base model:** `TinyLlama/TinyLlama-1.1B-Chat-v1.0`
- **Fine-tuning method:** LoRA (not QLoRA; no 4-bit quantization)
- **Precision:** FP16
- **Libraries:** Transformers, PEFT, Accelerate, Datasets, TRL, PyTorch

## Output

The notebook saves the LoRA adapter and tokenizer to a local directory named `tinyllama-sql-lora-adapter`. Model artifacts are intentionally not included in this repository; they can be regenerated by running the notebook.

## Limitations and safe use

- The results depend on the dataset, prompt format, training configuration, and base model.
- A small demo model may produce incorrect SQL, hallucinated columns, or queries that do not match the intended business logic.
- Before using generated SQL against real data, validate it against the database schema, parse or otherwise validate the query, and enforce read-only permissions and query limits.
- Do not commit credentials, private datasets, customer information, model checkpoints, or large generated files.
